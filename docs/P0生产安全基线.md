# P0 生产安全基线

## Apollo 强制基线

- Apollo 必须先于组合风险微服务启动；`APOLLO_ENABLED=true` 且 `APOLLO_REQUIRED=true`。
- 数据库、Redis、JWT、内部服务密钥、网关路由、Eureka、风险、MQ、邮件和运行参数必须发布在对应 Apollo namespace，微服务容器不得注入这些配置。
- 每次部署先执行 `scripts/publish-apollo-config.ps1`，逐 namespace 校验发布状态、必需键和未解析占位符。
- Apollo 不可访问或任一必需 namespace 为空时，应用必须失败关闭。
- 仅 Apollo Meta 地址、AppId/namespace 列表、基础设施容器密码和容器文件路径属于不可避免的启动引导配置。

## 部署前必须完成

1. 生成一套新的 RSA-2048 或更高强度密钥，旧密钥已视为泄露，不得继续使用。
2. 将私钥仅注入 `auth-service`；将公钥注入网关、认证、用户和系统服务。
3. 设置独立的 MySQL、Redis、Grafana 强密码，以及至少 32 个随机字节的 `INTERNAL_SERVICE_KEY`。
4. 为初始管理员生成 BCrypt 哈希并设置 `BOOTSTRAP_ADMIN_PASSWORD_HASH`。在 `.env` 中建议使用单引号包裹包含 `$` 的 BCrypt 值。
5. 仅在全新数据库执行 `database/init.sql`。已有数据库必须通过迁移脚本修改，禁止重新初始化。
6. 首次登录后确认管理员角色和权限来自数据库，并确认普通用户不能看到或调用 `risk:manage` 功能。

可在受控终端交互式生成管理员 BCrypt 哈希，命令会提示输入密码且不会把明文写入命令行：

```powershell
docker run --rm -it httpd:2.4-alpine htpasswd -nBC 12 admin
```

取输出中第一个冒号后的60位哈希作为 `BOOTSTRAP_ADMIN_PASSWORD_HASH`。该变量只在首次创建 MySQL 数据卷时生效；已有数据库必须通过受控变更流程重置管理员密码。

## 认证边界

- `/api/auth/**` 由网关转发至 `auth-service`；网关不再签发令牌。
- 令牌只使用 RS256 签名，不在网关保存私钥。
- 登录验证码为一次性随机值，保存在 Redis 中并在校验时删除。
- 密码使用 BCrypt；历史 SHA-256 密码在成功登录后自动升级。
- 会话严格保存在 Redis。Redis异常时登录和令牌校验均失败关闭。
- `/internal/**` 必须携带 `X-Internal-Service-Key`，且内部服务端口不对外发布。

## 验收检查

- 缺少任一必需环境变量时，Compose配置或应用启动失败。
- 无令牌访问业务API返回401；无权限访问返回403。
- 停止Redis后，已有令牌不可继续访问，且不能创建新会话。
- 直接访问 user-service 的 `/internal/users/enabled`，无内部密钥返回401。
- 前端菜单完全由服务端权限控制；六类通用风险数据刷新浏览器后仍来自数据库。
- 月末分析GET在数据库只读账号下可执行，且不会创建批次或变化明细。

## 已移除的演示能力

- 网关内置管理员认证。
- 固定验证码和浏览器本地验证码回退。
- 固定密码重置令牌和公开重置接口。
- 前端全量权限合并。
- 风险台账、评估、控制、整改、事件和指标的 localStorage 数据源。
- 月末查询自动生成演示历史批次。
