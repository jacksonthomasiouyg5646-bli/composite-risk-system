组合风险系统 / 业务价值与管理应用

组合风险业务价值宣导与展示方案

让业务看懂风险、理解影响、明确行动并评价效果

适用对象：管理层、业务部门、风险部门、经营机构及审计人员

文档版本：V1.0

编制日期：2026-07-24

1. 建设背景

组合风险系统已经具备客户、额度、申请、合同、债项、押品、逾期、违约、风险敞口、LGD、集中度、限额、月末变化、预警处置和智能分析等功能。下一步重点不是继续增加孤立指标，而是让业务人员清晰理解这些指标与业务增长、收益、限额、资本和损失之间的关系。

方案目标：将专业风险语言转化为业务决策语言，使业务人员能够回答“承担了多少风险、风险集中在哪里、环境恶化会损失多少、现在应该采取什么行动”。

2. 组合风险为什么重要

2.1 单户正常不代表组合安全

逐户授信主要判断某个客户是否可以准入，而组合风险关注全部客户叠加后是否形成行业、区域、产品、集团、押品或期限集中。大量单户均符合准入标准的业务，仍可能因为共同风险因素形成重大组合损失。

2.2 规模增长不等于价值增长

新增投放能够增加收入，同时也会增加预期损失、资本占用和限额消耗。只有扣除风险成本后仍能形成合理回报的业务，才是真正有价值的增长。

2.3 风险需要在损失发生前管理

逾期和违约是风险结果，PD迁徙、LGD上升、押品价值下降、行业集中度提高和额度快速占用是风险过程信号。组合风险管理通过提前识别这些信号，为压降、增信、定价、检查和退出争取时间。

业务价值定位：组合风险管理不是限制业务，而是帮助业务识别哪些领域可以继续增长、哪些业务需要提高价格、哪些客户需要追加保障、哪些集中领域必须压降，以及有限额度和资本应投向哪里。

3. 统一业务表达

页面正文优先展示业务含义，专业公式放入指标解释、下钻页或附录。

专业指标面向业务的表达业务要回答的问题
EAD客户违约时，本行实际面临的风险金额真正处于风险中的金额是多少？
PD客户未来发生违约的可能性客户出问题的可能性有多大？
LGD违约后扣除可回收部分仍可能损失的比例一旦违约，大约损失多少比例？
EL按当前风险水平预计发生的损失金额当前业务需要承担多少风险成本？
集中度风险是否过度集中于少数客户、行业或产品是否把风险集中在同一个方向？
限额占用距离本行风险承受边界还有多少空间还能做多少，是否需要调整结构？
压力损失环境恶化时可能新增的损失如果情况变差，损失会增加多少？
风险调整后收益扣除资金、运营和风险成本后的真实收益这笔业务是否真正值得做？

4. 用典型案例讲清业务价值

系统应提供“案例讲解模式”，选择一个典型客户，展示从授信、用信到风险计量和管理动作的完整链路。

客户授信 1 亿元
→ 当前已用信 8,000 万元
→ 违约概率 5%
→ 衰退 LGD 45%
→ 预计损失 180 万元
→ 押品价值下降后 LGD 升至 60%
→ 压力损失增加至 240 万元
→ 新增风险成本 60 万元
→ 触发追加担保、压降额度或提高定价

案例需要同时说明：客户当前没有逾期，并不代表没有组合风险；如果该客户所在行业已经高度集中，或多个客户依赖同类押品和同一经济因素，潜在损失会被共同放大。

5. 组合风险价值全景页

新增“组合风险价值全景”作为业务人员的统一入口，按“结论—来源—影响—行动”组织内容。

5.1 第一屏：现在风险怎样

  • 组合风险总体状态：正常、关注或承压。
  • 总EAD、平均EL、衰退EL和压力损失。
  • 本月新增风险金额以及与上月、年初、预算的差异。
  • 超限行业、超限客户和高LGD敞口数量。
  • 需要业务部门立即处理的重点事项。

页面顶部提供一句自动结论，例如：“本月组合风险总体关注，EAD增长3.2%，EL增长8.6%，增长主要来自制造业高PD客户和押品回收率下降。”

5.2 第二屏：风险来自哪里

  • 行业、产品、区域、机构和期限集中度。
  • 前十大客户及集团客户集中度。
  • 高PD、高LGD、高EAD客户交叉清单。
  • 押品不足、回收率下降和关联担保风险。
  • 从组合下钻到客户、合同、债项和支用明细。

5.3 第三屏：情况变差会怎样

  • 基准、轻度、中度和重度压力情景。
  • 各场景的预计损失及损失增量。
  • 对利润、拨备、资本和限额的影响。
  • 损失增量最大的行业、客户和产品。

5.4 第四屏：现在应该做什么

  • 暂停新增授信或压降存量额度。
  • 追加押品、保证或其他增信措施。
  • 提高贷款定价，覆盖新增风险成本。
  • 开展专项贷后检查或提高检查频率。
  • 调整行业准入和客户选择政策。
  • 形成整改任务并跟踪下月风险变化。

6. 风险与经营结果联动

业务人员最容易理解利润和资源占用，应在系统中将风险计量结果转换为经营影响。

风险调整后收益 = 业务收入－资金成本－运营成本－预期损失
风险调整后收益率 = 风险调整后收益 ÷ 资本占用
风险成本率 = 预期损失 ÷ 平均风险暴露
压力利润影响 = 压力损失－基准损失
业务现象组合风险解释建议动作
投放增长但风险调整后收益下降新增收入不足以覆盖新增风险成本和资本成本调整定价、客户结构或投放方向
行业收入较高但集中度超限单一共同风险因素可能造成组合损失放大限制增量、分散行业或设置退出计划
客户未逾期但LGD持续上升押品和回收能力下降，未来损失严重程度增加追加增信、重新估值或提前压降
业务收益较低且资本占用高资源使用效率不足提高定价或将资源转向更优客户

7. 突出月末变化与原因

组合风险系统本质上是月末批量分析系统，因此业务入口应优先回答“本月发生了什么变化”。

上月EL
＋新增投放影响
＋PD迁徙影响
＋LGD变化影响
＋新增违约影响
－回款及退出影响
－押品与处置改善
＝本月EL

建议使用瀑布图展示EL变化归因，并提供以下问题的自动解释：

  • 本月EAD、EL和高风险客户分别增加或减少多少。
  • 风险变化主要来自新增业务、存量迁徙还是模型参数变化。
  • 哪些行业、机构和客户贡献了最大风险增量。
  • 上月采取的处置措施降低了多少EAD、EL或超限占用。

8. 风险管理行动闭环

每个重大风险结论都必须能够形成具体行动，而不是停留在图表和预警颜色上。

发现风险 → 定位行业/客户/债项 → 解释原因 → 量化金额影响 → 生成管理建议 → 分配责任人 → 设置期限 → 跟踪处置 → 月末评价效果
闭环环节系统能力业务输出
识别集中度、限额、PD/LGD迁徙、逾期违约监测风险事件和重点清单
分析客户全景、损失测算、压力测试、AI辅助解释原因、影响金额和优先级
决策建议规则、审批、任务生成压降、增信、定价、检查或退出方案
执行责任人、完成期限、进度、证据上传可追踪整改任务
评价处置前后EAD、EL、风险等级和限额变化有效、部分有效或无效结论

9. 分角色展示方案

角色最关心的问题默认展示内容
管理层总体风险是否可控，利润和资本受何影响风险状态、损失金额、重大超限、趋势和决策事项
业务部门哪些客户还能做，哪些需要整改客户清单、额度空间、准入限制、定价建议和任务
风险部门风险来自哪里，模型和限额是否有效迁徙、集中度、LGD、压力测试、模型回溯和规则命中
经营机构本机构排名、问题客户和责任事项机构指标、同类对比、客户下钻和整改进度
审计与合规数据是否可靠，过程是否可追溯数据来源、规则版本、审批记录、操作日志和证据链

10. 页面交互与表达规范

  1. 所有指标同时展示当前值、上月值、变化值和状态。
  2. 红色只用于需要行动的超限和高风险事项，避免满屏告警。
  3. 金额优先于比例，结论优先于公式，变化原因优先于静态排名。
  4. 点击指标可查看分子、分母、纳入范围、计算日期和明细数据。
  5. 每个预警显示“为什么、影响多少、建议做什么、谁负责、何时完成”。
  6. AI结论必须附数据依据和规则依据，不允许只给无来源的判断。
  7. 月末数据必须标明批次号、数据日期、核验状态和是否封版。

11. 实施计划

阶段建设内容主要成果
第一阶段：看懂价值全景页、业务术语、自动结论、角色视图业务可快速了解总体状态和重点问题
第二阶段：算清EL变化归因、风险调整后收益、利润及资本影响说明风险变化原因和经营价值
第三阶段：行动打通预警、限额、定价、贷后检查和整改任务从风险发现到处置评价形成闭环
第四阶段：智能AI解释、外部数据、策略建议和效果学习提升分析效率并持续优化策略

13. 宣导与推广建议

  1. 面向管理层使用“一页结论+三个决策事项”，减少专业公式。
  2. 面向客户经理使用真实客户案例，演示风险如何影响额度、定价和检查要求。
  3. 每月发布一份组合风险简报，固定展示变化、原因、行动和效果。
  4. 建立指标词典和页面提示，确保不同部门使用同一业务口径。
  5. 将系统使用纳入月末经营分析和风险例会，不另建线下统计口径。

14. 预期成效

方案实施后，组合风险系统将从“风险指标展示平台”升级为“经营与风险共同决策平台”。业务人员能够理解风险对收益、额度和客户策略的实际影响；风险人员能够把专业判断转化为明确任务；管理层能够基于统一数据决定增长、定价、压降和资源配置。

最终判断标准：业务人员看到组合风险结论后，能够立即说清楚风险在哪里、影响多少钱、为什么发生、需要采取什么行动，以及行动后是否真正降低了风险。

本方案应与组合风险系统指标口径、月末批次管理、限额政策、预警规则及处置流程同步维护。规则或管理政策发生变化时，应更新版本并保留审批记录。
